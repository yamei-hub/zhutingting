关键实现答辩重点：为什么缩放“不跳”

要点做法原因
容器 overflow:hidden + touch-action:none + user-select:none 手势全部归自己管，阻止整页缩放与长按选中
双指距离 Math.hypot(x2-x1, y2-y1)，用同一套 client 坐标 勾股定理算两指直线距离，混用 client / page 会算错
缩放不跳 取两指中点为基准 f，按 t新 = f - (s新/s旧)·(f - t旧) 修正位移 保证“手指下方那一点”在缩放前后仍是同一点，视觉上不会突然平移
边界 缩放比例夹在 1～4；每帧按 (内容×scale - 容器)/2 夹住平移 既限制放大上限，也避免把图片拖出可视区留下黑边
1x 居中 scale 回到 1 时位移强制归零 缩回原大小时图片始终居中，不会“停在角落”
双击 两次点击间隔 <300ms、位移 <20px 才算双击；1x ↔ 2x，带 0.25s 过渡 用时间 + 位移双条件，避免拖动结束被误判成双击
旋转屏幕 resize / orientationchange 后重新量容器并夹一次位移 容器尺寸变了，旧位移可能越界；比例与位置保留，状态不丢

验收自检课程给的四条验收点

  • 缩放以两指中心为基准，图片不会“跳走”
  • 缩放到 1x 与 4x 边界时被限制，不会继续缩小 / 放大
  • 1x 时单指拖动没有任何位移（不能拖出边界）
  • 放大状态下旋转屏幕，比例与位置保留且不越界
  • 双击在 1x / 2x 之间切换，带 0.25s 过渡
!

踩坑记录答辩要讲的“缩放不跳”

坑：第一版只用 scale 缩放、不修正位移，两指一捏，图片就往左上角“窜”出去。
办法：把两指中点当成“不动的锚点”。设缩放前后比例 k = s新 / s旧，锚点相对容器中心为 f，则新位移 t新 = f - k·(f - t旧)。这样手指按住的那一点在屏幕上原地放大，看起来就完全不跳。

另一个坑：双指松开一根手指时，剩余那根会突然把图片“拽”一下。
办法：在 touchend 里判断剩余手指数，仍有一根时用当前位置重建拖动起点，状态不断档。
